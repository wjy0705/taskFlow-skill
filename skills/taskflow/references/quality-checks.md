# 质量检查参考

在第 3 问“结果有证据证明对吗？”时按需读取本文件。不要把这里的所有项目都当成每次必跑；只选择与当前技术栈、改动范围和风险相关的检查。

## 选择规则

- 改了代码：至少跑对应语言的测试、构建、lint 或类型检查之一。
- 改了接口：验证正常路径和一个关键异常路径。
- 改了数据库：检查迁移、写入结果、索引或回滚影响。
- 改了前端：用真实浏览器或构建结果验证关键交互。
- 改了安全相关逻辑：检查认证、鉴权、输入校验和敏感信息。
- 只做代码审查：输出文件路径、行号、影响和建议；不需要运行所有检查。
- 未运行的高相关检查必须说明原因，例如环境缺失、命令不存在、需要凭据、耗时过高、外部服务不可用或任务本身不需要。

## 通用证据

- `git diff` 或等效 diff：确认实际改动符合目标，没有无关变更。
- 测试输出：单元测试、集成测试或回归测试通过。
- 构建输出：编译、打包、类型检查或 lint 通过。
- 运行输出：服务启动、命令返回、日志中错误消失。
- 用户流程：复现步骤重新执行，原问题不再出现。
- 文件成品：打开、渲染或截图检查通过。
- 跳过说明：列出本应相关但未运行的检查，以及未运行原因。

## Java 后端

代码规范：

- 没有空 `catch` 块。
- `catch` 块记录日志、重新抛出，或明确处理异常。
- 没有硬编码密钥、token、密码。
- GET 请求不执行数据库写操作。
- Controller 返回格式与项目既有约定一致。

验证方式：

- `mvn test`、`mvn compile` 或项目约定的构建命令。
- 新接口提供 curl 验证命令。
- 错误路径有明确状态码和错误信息。
- 数据库写入检查表、字段和约束是否正确。

## Vue / 前端

代码规范：

- 没有 `console.log`、`debugger`、无意义注释代码残留。
- 接口调用沿用项目封装和错误处理方式。
- 加载、错误、空数据状态有处理。

验证方式：

- `npm run build`、`npm test`、类型检查或项目约定命令。
- 真实浏览器打开关键页面。
- 检查 console 错误。
- 对核心交互截图或跑端到端流程。

## API / 集成

- 后端服务能启动。
- 涉及接口能返回预期状态码和响应结构。
- 正向流程完整走通。
- 至少一个关键异常流程有合理响应。
- 涉及认证/鉴权的接口验证未授权和已授权两类情况。

## 安全

- 敏感接口有认证和授权。
- 外部输入有校验。
- SQL 或查询参数使用安全绑定方式。
- 日志不输出密码、token、密钥或完整个人敏感信息。
- 配置文件不新增明文凭据。
